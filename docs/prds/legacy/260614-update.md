对，这个思路更好。

`execute_code` 需要审批，说明完整 Hermes 可能在尝试用内置代码执行工具来“运行脚本 / 探测数据库”。但我们验证多表查询效果时，不应该依赖 `execute_code`。可以换成：

```text
Hermes 先查看数据库建表脚本
  ↓
理解表结构、字段、主外键
  ↓
再调用 db-query 插件生成 / 校验 / 执行 SQL
```

不过更推荐不要让 Hermes 直接读文件，而是给它一个 **只读 schema 工具**。

---

# 推荐调整

在插件里新增一个工具：

```text
db_get_schema_ddl
```

作用：

```text
返回示例数据库的建表 SQL / 表结构说明
```

这样 Hermes 不需要调用 `execute_code`，也不需要读文件，直接通过你的 db-query plugin 获取表结构。

# 新增工具实现

`hermes_plugins/db_query/tools.py` 增加：

```python
def db_get_schema_ddl(args=None, **kwargs):
    ddl = """
CREATE TABLE customers (
    customer_id INTEGER PRIMARY KEY,
    customer_name TEXT NOT NULL,
    city TEXT NOT NULL,
    signup_date TEXT NOT NULL
);

CREATE TABLE categories (
    category_id INTEGER PRIMARY KEY,
    category_name TEXT NOT NULL
);

CREATE TABLE products (
    product_id INTEGER PRIMARY KEY,
    product_name TEXT NOT NULL,
    brand_name TEXT NOT NULL,
    category_id INTEGER NOT NULL,
    list_price REAL NOT NULL,
    FOREIGN KEY (category_id) REFERENCES categories(category_id)
);

CREATE TABLE orders (
    order_id INTEGER PRIMARY KEY,
    customer_id INTEGER NOT NULL,
    order_date TEXT NOT NULL,
    status TEXT NOT NULL,
    channel TEXT NOT NULL,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);

CREATE TABLE order_items (
    order_item_id INTEGER PRIMARY KEY,
    order_id INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    quantity INTEGER NOT NULL,
    unit_price REAL NOT NULL,
    FOREIGN KEY (order_id) REFERENCES orders(order_id),
    FOREIGN KEY (product_id) REFERENCES products(product_id)
);

CREATE TABLE payments (
    payment_id INTEGER PRIMARY KEY,
    order_id INTEGER NOT NULL,
    payment_date TEXT NOT NULL,
    payment_method TEXT NOT NULL,
    amount REAL NOT NULL,
    status TEXT NOT NULL,
    FOREIGN KEY (order_id) REFERENCES orders(order_id)
);

CREATE TABLE refunds (
    refund_id INTEGER PRIMARY KEY,
    order_id INTEGER NOT NULL,
    order_item_id INTEGER,
    refund_date TEXT NOT NULL,
    refund_amount REAL NOT NULL,
    reason TEXT,
    status TEXT NOT NULL,
    FOREIGN KEY (order_id) REFERENCES orders(order_id),
    FOREIGN KEY (order_item_id) REFERENCES order_items(order_item_id)
);
"""

    relationships = [
        "customers.customer_id = orders.customer_id",
        "orders.order_id = order_items.order_id",
        "products.product_id = order_items.product_id",
        "categories.category_id = products.category_id",
        "orders.order_id = payments.order_id",
        "orders.order_id = refunds.order_id",
        "order_items.order_item_id = refunds.order_item_id",
    ]

    metrics = {
        "GMV": "SUM(order_items.quantity * order_items.unit_price)",
        "订单数": "COUNT(DISTINCT orders.order_id)",
        "有效订单": "orders.status IN ('paid', 'shipped', 'completed')",
        "支付金额": "SUM(payments.amount), where payments.status = 'success'",
        "退款金额": "SUM(refunds.refund_amount), where refunds.status = 'success'",
        "退款率": "退款金额 / GMV"
    }

    return to_json({
        "ok": True,
        "ddl": ddl,
        "relationships": relationships,
        "metrics": metrics
    })
```

# 修改 Skill 工作流

`SKILL.md` 里把流程改成：

```md
## Workflow

1. 如果用户问数据库、报表、销售、订单、商品、退款、支付相关问题，先调用 `db_get_schema_ddl` 了解表结构。
2. 再调用 `db_schema_search` 找相关表和指标。
3. 如果涉及多表，调用 `db_get_table_profile` 和 `db_get_join_paths`。
4. 生成 SQLite SELECT SQL。
5. 调用 `db_validate_sql` 校验。
6. 校验通过后调用 `db_execute_sql`。
7. 根据查询结果回答。
8. 不要调用 execute_code、terminal、file editing、browser 等工具来理解数据库。
```

# 最终链路

调整后，Hermes 的行为应该变成：

```text
用户问题
  ↓
db_get_schema_ddl
  ↓
db_schema_search
  ↓
db_get_table_profile
  ↓
db_get_join_paths
  ↓
生成 SQL
  ↓
db_validate_sql
  ↓
db_execute_sql
  ↓
生成答案
```

这样就不需要 `execute_code` 审批了。

核心点是：**不要让完整 Hermes 自己想办法运行脚本，而是把“查看建表脚本”也包装成一个安全、只读、无审批的 db-query 工具。**
