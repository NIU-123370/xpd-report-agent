# Hermes SQLite Demo 设计文档

## 目标

本项目用于验证完整 Hermes Agent 通过自定义数据库工具查询本地 SQLite 的能力。验证链路包括自然语言问题识别、schema 检索、表结构读取、JOIN 路径发现、SQL 生成前约束、SQL 安全校验、只读执行和结果解释。

首版不是生产系统，不做账号、多租户、复杂权限、数据脱敏、订阅报表或图表。

## 架构

```text
浏览器静态对话框
  -> FastAPI Wrapper
  -> Hermes API Server /v1/chat/completions
  -> Hermes Agent Runtime
  -> db-multitable-query Skill
  -> db-query Plugin Tools
  -> 本地 SQLite demo_ecommerce.sqlite
```

FastAPI Wrapper 只做代理，不直接生成或执行 SQL。这样可以确保验证对象仍然是完整 Hermes Agent，而不是本地 mock agent。

## 数据库

示例库由 `scripts/create_demo_db.py` 生成，默认路径为 `data/demo_ecommerce.sqlite`，也可通过 `HERMES_DEMO_SQLITE_PATH` 指定。

业务表：

- `customers`：客户
- `categories`：商品类目
- `products`：商品
- `orders`：订单主表
- `order_items`：订单明细
- `payments`：支付
- `refunds`：退款

核心口径：

- GMV：`SUM(order_items.quantity * order_items.unit_price)`
- 订单数：`COUNT(DISTINCT orders.order_id)`
- 有效订单：`orders.status IN ('paid', 'shipped', 'completed')`
- 支付金额：`SUM(payments.amount)` 且 `payments.status = 'success'`
- 退款金额：`SUM(refunds.refund_amount)` 且 `refunds.status = 'success'`
- 退款率：`refund_amount / gmv`

## Hermes Plugin

插件目录为 `hermes_plugins/db_query/`，Hermes 安装目录为 `~/.hermes/plugins/db-query/`。

工具：

- `db_get_schema_ddl()`：返回当前 SQLite 示例库的建表 DDL、外键关系和业务指标口径，作为 Hermes 理解数据库的只读入口。
- `db_schema_search(question, top_k)`：根据问题返回候选表、字段、指标和业务提示。
- `db_get_table_profile(tables, include_samples)`：返回表结构、主键、外键、索引、行数和样例数据。
- `db_get_join_paths(tables)`：基于 SQLite 外键元数据返回表间最短 JOIN 路径。
- `db_validate_sql(sql)`：用 `sqlglot` 和 SQLite `EXPLAIN QUERY PLAN` 校验只读 SELECT。
- `db_execute_sql(sql, max_rows)`：重新校验后只读执行，并返回结果、列名、耗时和截断状态。

安全策略：

- SQLite 使用 `mode=ro` 连接执行查询。
- Hermes 应通过 `db_get_schema_ddl` 理解表结构，不应调用 `execute_code`、terminal、shell、文件编辑或 browser 工具探测数据库。
- 本 demo 的 API Server 工具面应限制为 `db_query`，而不是使用默认 `hermes-api-server` 全工具集。
- 插件依赖必须安装在 Hermes 自己的 Python venv 中，否则 `sqlglot` 缺失会导致插件加载失败。
- 禁止多语句、DDL、DML、PRAGMA、命令类 SQL、`SELECT *`。
- 只允许访问示例库中已发现的表，允许 CTE 名称作为派生表引用。
- 执行前始终调用 `db_validate_sql`。
- `db_execute_sql` 通过外层 `LIMIT max_rows + 1` 实现结果截断。

## Skill

`skills/db-multitable-query/SKILL.md` 约束 Hermes 在数据库、报表、销售、订单、商品、客户、支付、退款相关问题中使用 `db-query` 工具，不凭空回答。

工作流固定为：

1. 调用 `db_get_schema_ddl` 理解 SQLite schema。
2. 理解问题和默认时间范围。
3. 调用 `db_schema_search`。
4. 调用 `db_get_table_profile`。
5. 多表问题调用 `db_get_join_paths`。
6. 生成 SQLite SELECT。
7. 调用 `db_validate_sql`。
8. 校验通过后调用 `db_execute_sql`。
9. 输出结论、假设、结果摘要、SQL 和注意事项。

## FastAPI Wrapper 与前端

Wrapper 目录为 `app/`。

接口：

- `GET /`：静态聊天页面。
- `GET /health`：wrapper 状态和 Hermes 健康检查结果。
- `POST /api/chat`：非流式代理 Hermes chat completions。
- `POST /api/chat/stream`：SSE 代理 Hermes chat completions。

环境变量：

- `HERMES_GATEWAY_HOST` / `HERMES_GATEWAY_PORT`：Hermes gateway 地址。
- `HERMES_GATEWAY_API_KEY`：本地 Hermes gateway bearer token。
- `HERMES_GATEWAY_MODEL`：wrapper 请求 Hermes gateway 时使用的模型名，默认 `hermes-agent`。
- `HERMES_LLM_*`：Hermes 调用底层模型供应商的配置。

前端使用原生 HTML/CSS/JS，不引入构建链路。

`GET /health` 还会读取 Hermes `/v1/toolsets`，确认 API Server 当前暴露了 6 个必需的 `db-query` 工具。
